# Framework content schema (version 1)

Framework content ships inside the app as JSON under `App/Resources/Content/`:

```
Content/
  index.json                                  summary of every framework and mapping (fast launch path)
  frameworks/<framework-id>.framework.json    one file per framework
  mappings/<from>_to_<to>.mapping.json        one file per NIST-published mapping
```

All three are generated by `tools/oscal_convert/convert.py` from the pinned NIST sources in
`data/sources/` plus the editorial overlays in `data/editorial/`. Never edit generated files
by hand: CI runs `convert.py --check` and fails if they drift.

Machine-readable schemas: [`schema/framework.schema.json`](../schema/framework.schema.json) and
[`schema/mapping.schema.json`](../schema/mapping.schema.json) (JSON Schema 2020-12).

## Adding a framework

1. Add its source files to `fetch_sources.py` and run it.
2. Add a builder in `frameworks.py` that emits the structure below, and call it from `convert.py`.
3. Add `data/editorial/<id>.json` with at least the `summary` block.
4. Run `convert.py`. The app discovers every `*.framework.json` in the bundle, so no app code
   changes are needed.

## Framework file

| Key | Type | Notes |
|---|---|---|
| `schemaVersion` | `1` | Bumped only for breaking changes. The app refuses files with a newer major version. |
| `id` | slug | Stable identifier, e.g. `csf-2.0`, `sp800-53r5`, `sp800-171r3`. User answers are keyed by it. |
| `shortName`, `title`, `publisher`, `publicationId`, `version` | string | Display metadata. `version` is the publication's version (e.g. `5.2.0`). |
| `contentVersion` | `YYYY.M.N` | Version of this app content build (from `data/content.json`). |
| `source` | object | Provenance: OSCAL URL, oscal-content commit, catalog version and last-modified date, sha256, retrieval date, and publication / CPRT links. |
| `summary` | object | Plain-language explorer text: `plainDescription`, `audience`, `covers`, `typicalEffort`, `whenToChoose`. Editorial. |
| `notices` | array | `{id, title, body}` callouts, e.g. the SP 800-171 CMMC revision notice. Editorial. |
| `kinds` | array | Requirement kinds with display names, e.g. `control` / `enhancement`. |
| `groupLevels` | array | Display names per group depth, e.g. `Function`, `Category`. Length equals the group tree depth. |
| `baselines` | array | Optional. `{id, title, additive, summary}`. `additive: true` means it is layered on top of another baseline (Privacy). |
| `tiers` | array | Optional (CSF). Added in Phase 3. |
| `groups` | tree | `{id, displayId, title, description?, groups?, requirementIds?}`. A group has either sub-groups or requirements. `requirementIds` lists top-level requirements only; children are found by `parentId`. |
| `requirements` | array | Flat, in document order (`sortKey`). See below. |
| `withdrawn` | array | Withdrawn items kept for lookup only: `{id, displayId, title?, incorporatedInto?, movedTo?, addressedBy?}`. Never shown as questions. |

### Requirement

Every question in the app maps to exactly one requirement.

| Key | Type | Notes |
|---|---|---|
| `id` | string | Stable ID used for storage and mappings: `GV.OC-01`, `ac-2.1`, `03.01.01`. |
| `displayId` | string | Shown in SF Mono: `GV.OC-01`, `AC-2(1)`, `03.01.01`. |
| `kind` | slug | One of the framework's `kinds`. |
| `title` | string | Control title. For CSF subcategories (which have no title), the outcome statement. |
| `groupId` | string | Owning group. |
| `parentId` | string | Optional. The base control of an SP 800-53 enhancement. |
| `sortKey` | string | Document order. |
| `statement` | items | The requirement text as a tree of `{label?, text?, items?}`. |
| `discussion` | string | NIST discussion text (SP 800-53, SP 800-171). |
| `examples` | items | CSF 2.0 Implementation Examples. |
| `objectives` | items | Assessment objectives (SP 800-53A, SP 800-171A), used for "what done looks like". |
| `parameters` | array | Organization-defined parameters: `{id, displayLabel?, label?, usage?, guidance?, choices?, howMany?, aggregates?, altId?}`. A parameter with `aggregates` is a display-only roll-up of other parameters. |
| `baselines` | array | SP 800-53B baselines that include this item. |
| `implementationLevels` | array | SP 800-53 `organization` / `system`. |
| `related` | array | Related requirement IDs in the same framework. |
| `references` | array | NIST publications only (`{title, url?}`). Third-party standards are removed. |
| `sourceUrl` | URL | The matching page in NIST CPRT. |
| `editorial` | object | Optional plain-language layer: `question`, `whyItMatters`, `doneLooksLike`, `nextSteps[]`, `reviewed`. |

### Text tokens

Statement text and parameter choices contain `{{param:<id>}}` where an organization-defined
value belongs. The app replaces the token with the user's value, or with the parameter label
when no value is set. An SP 800-53 token may refer to a parameter defined on the base control
or on a sibling enhancement, so the app resolves tokens within the whole control family tree
(base control plus enhancements).

## Mapping file

| Key | Type | Notes |
|---|---|---|
| `id` | string | `<from>_to_<to>`. |
| `fromFramework`, `toFramework` | string | Framework IDs. Lookups work in both directions. |
| `relationship` | object | `{type, description}`. `type` is `source-control` (SP 800-171 → SP 800-53) or `informative-reference` (CSF 2.0 → others). |
| `source` | object | Where NIST publishes the mapping, with hash and retrieval date. |
| `entries` | array | `{from, to: [ids]}`. |
| `unresolved` | array | Published references that could not be represented (withdrawn targets, family-level references). Kept for transparency; not used by the app. |

The app never infers, chains, or edits mappings. If NIST does not publish a relationship, it does not exist in the app.

## Editorial overlay (`data/editorial/<id>.json`)

```json
{
  "frameworkId": "csf-2.0",
  "summary": { "plainDescription": "…", "audience": "…", "covers": "…", "typicalEffort": "…", "whenToChoose": "…" },
  "notices": [ { "id": "…", "title": "…", "body": "…" } ],
  "requirements": {
    "GV.OC-01": {
      "question": "…", "whyItMatters": "…", "doneLooksLike": "…", "nextSteps": ["…"], "reviewed": false
    }
  }
}
```

The converter lints overlays: no emoji, no exclamation marks, no marketing phrases, no unknown
IDs, no empty fields. `convert.py --require-editorial` additionally fails when an in-scope
requirement has no overlay. In scope means all CSF and SP 800-171 items, plus every SP 800-53
item in at least one baseline.
